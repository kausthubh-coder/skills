# You're on my cloud machine

You run in T3 Code on my InstaBox machine: Debian Linux, 4 vCPU, 8 GB, not my Windows laptop. T3 works as it does locally: its tools, terminal, browser tabs and diff panel all see this machine. I start threads here so the work keeps going while my laptop sleeps.

- Repos are in `~/dev/<repo>`. The Windows paths above (`C:\Users\...`, `~/.skills-parked`) are on my laptop and don't exist here. The parked vendor skills (Convex, Vercel, Cloudflare, Clerk, HyperFrames) aren't here either, so use the vendor's docs.
- **Agents here get about 4 GB, not 8.** T3 runs every thread's agents in one group that the kernel slows down past 4.2 GB and kills past 6.3 GB, and `/tmp` is in RAM. Over the limit nothing errors: commands just hang, so it looks like an app bug or an idle machine. On Oct 22, two potli dev servers froze every thread on t3-2 for 8 hours, and krida's model checker filled `/tmp` until `java -version` took a minute. So:
  - Run one dev server or heavy build per machine at a time. Before a big job, check `uptime` and `cat /sys/fs/cgroup/user.slice/user-$(id -u).slice/user@$(id -u).service/app.slice/app-t3code.slice/app-t3code-agents.slice/memory.current`; above about 3.5 GB or a load over 8, wait or lean on CI.
  - When a command hangs, check load and memory before you blame the code.
  - Large scratch files go under `~/.cache`, not `/tmp`.
- **Processes.** Start a server in its own process group and stop the group: `setsid --fork sh -c 'echo $$ > /tmp/<name>.pid; exec <cmd>' > /tmp/<name>.log 2>&1`, then `kill -- -$(cat /tmp/<name>.pid)`. Never `pkill -f` or `pgrep -f`: the pattern matches your own shell, and agents hit their own shell that way six times on Oct 22. Stop everything you started before you end your turn, unless you leave it running for me on purpose and say how to stop it.
- **The machine pauses** after 30 minutes with no agent working, no terminal use and little CPU, and paused processes freeze. Never end a turn while CI, a deploy, Devin, a background job or your own subagents are still running: they stop, and their results never reach my thread. Taru's two helpers froze for 8 hours that way. Wait inside the turn with `run_in_background` and a Monitor, not a foreground `sleep` loop: a loop blocks your replies to me for up to 10 minutes.
- **Every change goes through a PR here, in every repo**, even ones that push straight to `main` from my laptop. Open it with `gh`, which is signed in as me and works normally. Don't merge until I say ship; then follow `ship-<app>`. Domain, DNS and hosting settings count as shipping too. Never merge a PR another thread owns. Push after every unit of work worth keeping: commits that exist only on this machine are lost if it's reset.
- **Logins and tokens.** Browser logins (`wrangler login`, `vercel login`) can't call back to this machine. When a step needs one, ask me for an API token up front and use it as the tool's env var or config. Tokens I paste in chat are fine: use them, don't warn me.
- **I can't open files on this machine.** Show me a page with `html_render`, or serve it and open it in a T3 browser tab. Show an image by embedding it, not by its path. Don't point me to laptop threads by id from here either: this machine can't read them, and I can't start a laptop thread from here.
- **Test everything you can here first**, with the repo's `verify-<app>` skill: web apps in T3's browser tabs or Playwright, CLIs, backends, tests. A desktop app that runs on Linux can run on the machine's desktop (`DISPLAY=:1`). Chromium is at `/usr/bin/chromium`; pass it as `executablePath` when Playwright's own browser is missing.
- **What this machine can't run:** no KVM, no device hub, no Mac, no Windows. Don't try the Android emulator here: krida's software emulator ran 87 minutes and never fit in memory.   - Run the test script yourself first, as far as this machine allows. Krida's first Devin session went to debugging a script nobody had run.
  - At most two sessions at once. Test a stack of PRs in one session, not one session per PR.
  - Start with `devin_session_create`, the prompt in `~/.cloud/agent-skills/cloud/devin-test.md`, the PR's repo and the platform.   - On `out_of_quota`, start nothing more on Devin today. Report what went untested.
