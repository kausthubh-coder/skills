Shared skills have different jobs

Frame and start

  • init-project starts a fresh project.
  • optimize audits an existing one.
  • grilling tests a decision through questions.
  • sharpen rewrites the task before work starts.

Build and repair

  • diagnosing-bugs builds a failing reproduction.
  • correct prevents a repeated mistake.
  • codebase-design guides module boundaries.
  • principle-minimize-reader-load makes code easier to trace.
  • no-comments reviews comments on a diff.

Run and prove

  • create-project-flows writes setup and ship skills.
  • create-verification-skill writes real-app checks.
  • maintain-verification-skill keeps those checks current.
  • principle-prove-it-works, behavior testing and benchmark-checklist set the proof standard.
  • Formal verification checks named properties under explicit assumptions.

Design and explain

  • critly supplies design concepts; critly-audit applies them.
  • html-artifacts creates pages people read.
  • unslop edits prose.
  • writing-for-agents shapes agent documentation.
  • bro explains the last answer; in-your-own-words checks the understood goal.

Coordinate work

  • delegating sets the brief and review standard.
  • threads reaches the laptop and Mac mini.
  • handoff preserves context for another agent.

Maintain the library

  • my-skills changes the shared library.
  • audit-skills reads real runs and feeds the dashboard.
  • Eval scenarios check behavior; trigger tests check skill selection.

One source reaches both agents

What gets linked, parked or retired

link.mjs discovers library skills and local sources listed in sources.json. It also installs global rules and search hooks.

Project skills stay inside their repo. This repo's audit-skills is a project skill, separate from skills/*.

Convex, Vercel and Cloudflare copies come from park.mjs. Clerk and HyperFrames also have parked routing in global/skills.md.

_retired/ is reference material. Old entries in sources.json do not make a retired skill active.

Real runs improve the library

The checks and distribution loop

Behavior evals run skills in isolated test threads. The manager checks the output, grades it and writes a local HTML report.

Trigger tests check whether agents select the right skill. Rerun them after description or routing changes.

Use writing-for-agents for skill instructions and unslop for prose. Reusable skills belong here; a skill for one repo stays in that repo.

node scripts/link.mjs adds or prunes links and updates global rules. Existing linked source edits are already visible locally.

Commit and push library changes. sync.mjs is configured to pull this repo and Critly every five minutes, then relink if they moved.

upstream.mjs detects adopted upstream changes. sources.json records provenance and local modifications.

Private thread quotes, usage data and eval reports stay in the ignored reports/ folder.

Vendor skills and project-generated skills

Vendor families are routed from global/skills.md: Convex, Vercel, Cloudflare, Clerk and HyperFrames. They are intentionally outside this shared-skill index.

Generated project skills include worktree-<app>, verify-<app>, ship-<app> and named formal-verification skills. Their exact names and commands depend on the repo.

"You invoke" records the explicit-only metadata. A named skill may still call another skill, as init-project calls grilling.
